## Codebase Patterns
- The npm workspaces are ordered shared, CLI, then web so production builds make shared package artifacts available to downstream packages.
- Development type checks resolve `@codevis/shared` directly to its TypeScript source; CLI production builds resolve the already-built declaration output.
- Solidity relationship resolution should use compiler AST declaration IDs and normalized source-unit paths rather than matching symbol labels.
- CLI commands should keep validated JSON on stdout and route progress plus source-linked compiler diagnostics to stderr.
- The web client loads validated graph data from `/api/graph`; development and production smoke tests use the static fixture at that path until the watch service owns the endpoint.
- Progressive graph visibility should follow `contains` ancestry, with files initially expanded for architecture and contracts initially collapsed; filter edges to visible endpoints whenever nodes are hidden.
- Source inspection reads repository-relative file contents from the validated graph's `metadata.sources` map and uses node line/column ranges for excerpts and highlights.
- Graph filtering should be applied after progressive containment visibility, while search explicitly expands all `contains` ancestors before selecting and focusing a hidden result; security presets may bypass collapsed detail but should retain visible hierarchy.
- The production watch service serves `apps/web/dist` on `127.0.0.1` and owns the existing `/api/graph` boundary; expose a programmatic close method so command signals and integration tests share the same shutdown path.
- Live watch updates use stable node IDs and serialized, debounced analysis; `/api/graph` always returns the latest validated snapshot while `/api/events` pushes the same payload over server-sent events.
- Session work events use the independently validated shared event schema and travel in `graph.metadata.workEvents`; accept semantic agent events through `POST /api/work-events` and keep malformed input isolated from the active session.
- Run Foundry with direct argument arrays and `shell: false`; keep its JSON test result model independent from graph mapping so CLI execution and later live visualization can share it.
